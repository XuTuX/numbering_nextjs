# NUMBERING 게임 로직 이식용 Codex 작업 지시서

아래의 **붙여넣기용 작업 프롬프트**를 새 프로젝트의 Codex 작업에 그대로 전달한다. 그 아래의 상세 명세는 구현 중 판단 기준과 테스트 기준으로 사용한다.

## 붙여넣기용 작업 프롬프트

```text
현재 프로젝트에 NUMBERING의 게임 로직을 이식해줘.

목표:
- 수식 공방, 수열 탐정, 숫자 금고의 솔로 게임 로직을 구현한다.
- 프로젝트에 실시간 통신 기반 멀티플레이가 있다면 같은 문제를 공유하는 3라운드 멀티플레이도 구현한다.
- 기존 프로젝트의 언어, 프레임워크, 폴더 구조, 상태 관리, UI 스타일을 우선 존중한다.
- 게임 규칙과 판정은 아래 상세 명세를 단일 진실 공급원으로 삼는다.
- 수식 판정과 문제 생성은 UI에서 분리한 순수 함수로 만들고 단위 테스트를 작성한다.
- 멀티플레이에서는 클라이언트를 신뢰하지 말고 서버가 문제의 정답, 제출 내용, 점수, 타이머를 판정한다.
- 구현 전에 현재 저장소 구조와 기존 테스트/린트 명령을 확인한 뒤, 필요한 파일만 수정한다.
- 구현 후 관련 단위 테스트, lint, typecheck/build를 실행하고 결과를 보고한다.

핵심 규칙:
1. 수식 공방: 주어진 숫자 문자의 순서를 바꾸지 않고 모든 숫자를 정확히 한 번 사용한다. 숫자 사이에 +, -, ×, ÷, =을 넣거나 아무것도 넣지 않아 여러 자리 수로 이어 붙일 수 있다. 연속한 숫자 범위에는 괄호를 넣을 수 있다. 등호는 정확히 하나이고 양변의 정수 계산값이 같아야 한다.
2. 수열 탐정: 1~9의 두 시작 수 a, b에서 다음 항을 직전 두 항의 합으로 만든다. 플레이어에게 마지막 값과 전체 항 개수만 보여주고 순서가 있는 (a, b)를 맞히게 한다. 출제 문제는 1~9 전체 후보에서 답이 정확히 하나여야 한다.
3. 숫자 금고: 2~9의 한 자리 숫자 3~5개를 순서를 자유롭게 바꾸고, 모든 수를 정확히 한 번 사용하며, 모든 숫자 사이에 +, -, ×, ÷ 중 하나를 넣고 괄호를 사용할 수 있다. 계산 결과가 목표값과 같으면 성공이다.
4. 계산기는 eval을 쓰지 말고 토큰화 + 연산자 우선순위로 구현한다. ×/÷가 +/-보다 우선하며 괄호를 지원한다. 0으로 나누기와 나누어떨어지지 않는 나눗셈은 무효다. 단항 음수와 소수는 허용하지 않는다.
5. 솔로 난이도는 1~2라운드 EASY, 3~4 NORMAL, 5라운드부터 HARD다. 수열은 1~2라운드 5항, 3~4라운드 6항, 5~6라운드 7항, 7라운드부터 8항이다.
6. 멀티플레이는 3라운드이고 EASY/NORMAL/HARD 순서다. 각 라운드는 기본 180초, 라운드 사이는 기본 10초다. 수식 공방은 서로 다른 정답 수식을 제출할 때마다 1점, 나머지 두 게임은 라운드당 플레이어별 최초 정답만 1점이다.

상세 구현 규칙, 생성 템플릿, 이벤트 계약, 완료 조건은 docs/GAME_LOGIC_HANDOFF.md의 나머지 내용을 따른다. 대상 프로젝트에 이 파일이 없다면 이 프롬프트 뒤에 함께 전달된 상세 명세를 사용한다.
```

## 1. 공용 수식 모델

### 데이터 타입

```ts
type InlineOperator = '+' | '-' | '×' | '÷' | '=';

type OperatorSlot = {
  index: number; // digits[index]와 digits[index + 1] 사이
  operator: InlineOperator | null;
};

type ParenthesisRange = {
  id: string;
  startDigitIndex: number;
  endDigitIndex: number;
};
```

숫자 항목이 `n`개이면 연산자 슬롯은 `n - 1`개다. 슬롯이 `null`이면 다음 숫자와 그대로 이어 붙여 여러 자리 정수를 만든다.

### 수식 문자열 조립

숫자를 왼쪽부터 순회하며 다음 순서로 문자열을 만든다.

1. 현재 인덱스에서 시작하는 괄호 수만큼 `(`를 붙인다.
2. 현재 숫자를 붙인다.
3. 현재 인덱스에서 끝나는 괄호 수만큼 `)`를 붙인다.
4. 마지막 숫자가 아니라면 해당 슬롯의 연산자를 붙인다. 슬롯이 비었으면 아무것도 붙이지 않는다.

예: 숫자 문자가 `['1','9','1','4','5']`이고 슬롯이 `[null, '=', null, '+']`이면 `19 = 14 + 5`가 된다.

### 괄호 범위 규칙

- 한 숫자만 묶을 수 없다.
- 시작과 끝의 입력 순서는 상관없으며 작은 인덱스를 시작점으로 정규화한다.
- 완전히 같은 범위를 중복 생성할 수 없다.
- 괄호 범위끼리 교차할 수 없다. 예: `[0, 2]`와 `[1, 3]`은 불가하다.
- 서로 분리된 범위와 완전히 포함되는 중첩 범위는 허용한다.
- 숫자 순서가 바뀌는 숫자 금고에서는 재배열 직후 모든 괄호를 제거한다.

### 안전한 계산기

허용 토큰은 0 이상의 정수 리터럴, `+`, `-`, `×`, `÷`, `(`, `)`다. 공백은 무시한다.

- 우선순위: `×`, `÷` = 2 / `+`, `-` = 1
- 같은 우선순위는 왼쪽부터 계산한다.
- 암시적 곱셈, 단항 연산자, 소수, 빈 괄호, 알 수 없는 문자는 허용하지 않는다.
- `a ÷ b`에서 `b === 0`이면 무효다.
- `a % b !== 0`이면 무효다. 즉, 모든 나눗셈 중간 결과가 정수여야 한다.
- 결과 타입은 성공 시 `{ valid: true, value }`, 실패 시 `{ valid: false, message }` 형태로 유지한다.
- 언어 런타임의 `eval`, `Function`, 임의 코드 실행은 사용하지 않는다.

## 2. 수식 공방

### 플레이 규칙

- 입력은 `digitString`과 이를 한 문자씩 나눈 `digits`다.
- 플레이어는 숫자 문자의 위치와 순서를 바꿀 수 없다.
- 모든 숫자를 정확히 한 번 사용해야 한다.
- 빈 슬롯은 인접 숫자를 이어 붙인다.
- 사용할 수 있는 기호는 `+`, `-`, `×`, `÷`, `=`와 괄호다.
- 등호는 정확히 하나여야 하고 양쪽 모두 비어 있지 않아야 한다.
- 등호 양쪽을 공용 계산기로 계산했을 때 값이 같으면 정답이다.
- 숫자 보존은 수식에서 숫자가 아닌 모든 문자를 제거한 문자열이 원본 `digitString`과 정확히 같은지로 검사한다.
- 솔로에서는 올바른 수식이 완성되는 즉시 성공한다. 제한 시간은 없고 경과 시간을 표시한다.
- 라운드당 힌트는 3회다. 힌트 후보는 정답에 포함된 임의 기호, 괄호 필요 여부, 양변의 값이다.

### 난이도와 생성기

난이도별 숫자 문자 수는 EASY 5개, NORMAL 6~7개, HARD 7~10개다. 생성기는 먼저 항상 참인 등식을 만든 뒤 기호와 괄호를 제거한 숫자 문자열을 문제로 사용한다.

후보 공통 필터:

- 기준 결과값은 1~999다.
- 템플릿 변수는 모두 정수이며 1 이상이어야 한다.
- 난이도별 숫자 문자 수 범위에 들어야 한다.
- 공용 수식 검증기로 실제 참인 등식이어야 한다.
- 최근 생성한 `digitString` 20개와 같으면 다시 생성한다.
- 최대 500회 시도 후 고정 문제로 대체한다.

템플릿 목록:

```text
EASY
A + B = C
A - B = C
C = A + B
C = A - B
A × 1 = A

NORMAL
A × B = C
A ÷ B = C
A + B × C = D
A × B - C = D
A ÷ B + C = D
A + B - C = D
D = A + B × C
D = A × B - C
D = A + B - C
A + B = C - D
A - B = C + D
A × B = C + D
A × B = B × A
A × 1 = A + 0

HARD
(A + B) × C = D
A × (B - C) = D
(A - B) ÷ C = D
(A + B) ÷ C = D
A × (B + C) = D
(A + B) × C - D = E
A × (B + C) ÷ D = E
E = (A + B) × C - D
E = A × (B + C) - D
E = (A - B) × C + D
(A + B) × C = D + E
A × (B + C) = D - E
A + B × C = D - E
```

구현 시 각 변수 범위를 꼭 현재 코드와 완전히 같게 복제해야 하는 요구가 없다면, 위 템플릿이 항상 공통 필터를 통과하도록 합리적인 양의 정수 범위를 사용한다. 나눗셈 템플릿은 역산해서 항상 나누어떨어지게 만든다. 정답의 유일성은 요구하지 않는다.

고정 대체 문제:

- EASY: `19 = 14 + 5` → `19145`
- NORMAL: `45 = 12 + 33` → `451233`
- HARD: `104 = (12 + 14) × 4` → `10412144`

참고: 기존 생성기에는 `A + 0 = A`와 `A × 1 = A + 0` 템플릿도 있지만 공통 필터가 모든 변수를 1 이상으로 제한해 실제로는 선택되지 않는다. 기존 동작을 보존하려면 제외하고, 의도대로 살리려면 공통 필터를 `0 이상`으로 바꾸는 별도 제품 결정을 남긴다.

## 3. 수열 탐정

### 생성과 판정

- 시작 수 `first`, `second`는 각각 1~9다. 순서가 있는 쌍이므로 `(2, 4)`와 `(4, 2)`는 다른 답이다.
- 수열은 `[first, second]`에서 시작한다.
- 이후 항은 항상 직전 두 항의 합이다.
- 플레이어에게는 마지막 항 `target`과 전체 항 개수 `termCount`만 공개한다.
- 해당 `termCount`에서 1~9의 모든 81개 시작 쌍을 전수 조사했을 때 같은 `target`을 만드는 쌍이 정확히 하나인 문제만 후보로 사용한다.
- 정답 제출은 두 값과 정답의 순서까지 정확히 같아야 한다.
- 오답 횟수 제한은 없다. 솔로에서는 시도 횟수를 표시하고 정답 후 전체 수열을 공개한다.

난이도:

| 솔로 라운드 | 전체 항 수 |
|---|---:|
| 1~2 | 5 |
| 3~4 | 6 |
| 5~6 | 7 |
| 7 이상 | 8 |

## 4. 숫자 금고

### 플레이 규칙

- 각 숫자는 2~9의 한 자리 수다. 같은 숫자가 여러 번 나올 수 있다.
- 플레이어는 숫자의 순서를 자유롭게 재배열할 수 있다.
- 제시된 숫자 멀티셋을 정확히 한 번씩 모두 사용해야 한다.
- 모든 인접 숫자 사이의 슬롯에 `+`, `-`, `×`, `÷` 중 하나를 넣어야 한다. `=`은 사용하지 않는다.
- 괄호는 공용 괄호 범위 규칙을 따른다.
- 공용 계산기의 결과가 `target`과 같으면 정답이다.
- 솔로에서는 정답이 완성되는 즉시 성공하며 경과 시간을 멈춘다.
- 라운드당 힌트는 3회이며, 정답 예시 수식에 들어가는 임의 연산자 하나를 알려준다.

### 난이도와 생성기

| 라운드 | 난이도 | 숫자 개수 |
|---|---|---:|
| 1~2 | EASY | 3 |
| 3~4 | NORMAL | 4 |
| 5 이상 | HARD | 5 |

숫자 3~5개를 먼저 만든 뒤 아래 템플릿 중 하나로 정답과 목표를 만들고, 표시할 숫자 순서만 섞는다. 목표값은 10~250인 정수여야 한다. 최대 200회 시도한다. 정답 유일성은 요구하지 않는다.

```text
3개: (a+b)×c | a×b+c | a×b-c
4개: (a+b)×c-d | a×b+c×d | (a+b)×(c-d) | a×b-c+d
5개: (a+b)×c+d-e | a×b+c×d-e | (a+b)×(c+d)-e | a×b-c+d×e
```

고정 대체 문제:

- EASY: 숫자 `[2,3,4]`, 목표 `20`, 예시 정답 `(2+3)×4`
- NORMAL: 숫자 `[2,3,4,5]`, 목표 `29`, 예시 정답 `2×3×4+5`
- HARD: 숫자 `[2,3,4,5,6]`, 목표 `20`, 예시 정답 `2×3+4×5-6`

## 5. 솔로 진행 규칙

- 모든 솔로 모드는 라운드 1부터 시작하며 정답 후 다음 문제로 넘어간다.
- 새 문제에서 라운드, 난이도, 문제 데이터, 편집 상태, 힌트 3회, 타이머를 초기화한다.
- 수식 공방과 숫자 금고 타이머는 0부터 증가하며 정답 순간 멈춘다.
- 수열 탐정은 제한 시간 대신 현재 문제의 제출 시도 횟수를 센다.
- 초기화는 현재 문제만 원래 상태로 되돌리고 라운드, 문제, 타이머, 남은 힌트는 유지한다.

## 6. 멀티플레이

### 방과 라운드 상태

```ts
type RoomStatus = 'LOBBY' | 'PLAYING' | 'ROUND_END' | 'GAME_END';
type GameMode = 'formula-workshop' | 'sequence-detective' | 'number-vault';
```

- 방 코드는 충돌하지 않는 임의의 영문 대문자/숫자 4자리다.
- 방 정원은 5명이다.
- 방장만 `LOBBY`에서 게임을 시작할 수 있다.
- 총 3라운드다.
- 멀티 라운드 1/2/3은 솔로 진행도 라운드 1/3/7을 사용해 각각 EASY/NORMAL/HARD 문제를 만든다.
  - 수식 공방: EASY/NORMAL/HARD
  - 수열 탐정: 5항/6항/8항
  - 숫자 금고: 숫자 3개/4개/5개
- 라운드 시간 기본값은 180초, 라운드 사이 결과 화면은 10초다. 환경 변수 등으로 바꿀 수 있게 한다.
- 서버가 1초마다 시간을 감소시키고 모든 참가자에게 동기화한다.
- 3라운드 종료 후 점수 내림차순으로 최종 순위를 표시한다. 동점 추가 규칙은 없다.

### 점수와 조기 종료

- 수식 공방: 같은 라운드에서 플레이어가 서로 다른 올바른 등식을 찾을 때마다 1점이다. 공백만 제거한 문자열이 이미 제출 목록에 있으면 중복이다. 정답 제출 후 편집기를 비워 계속 찾을 수 있다. 모든 플레이어가 풀었다는 개념과 조기 종료는 없다.
- 수열 탐정: 플레이어별 라운드 최초 정답만 1점이다.
- 숫자 금고: 플레이어별 라운드 최초 정답만 1점이다.
- 수열 탐정과 숫자 금고는 현재 연결된 모든 플레이어가 풀면 즉시 `ROUND_END`로 넘어간다.
- 각 새 라운드에서 제출 목록과 해결 여부를 초기화한다. 누적 점수는 유지한다.

### 서버 검증

- 서버 메모리에 실제 문제 정답을 보관하고, 공개 payload에는 필요한 문제 정보만 넣는다.
  - 수식 공방 공개: `digits`, `digitString`
  - 수열 탐정 공개: `target`, `termCount`; 비공개: `first`, `second`
  - 숫자 금고 공개: `numbers`, `target`; 예시 정답 수식은 공개하지 않음
- 모든 제출은 방 존재, `PLAYING` 상태, 게임 모드, 연결된 참가자 여부부터 확인한다.
- 수식 공방은 서버에서 숫자 순서/보존, 등호 개수, 양변 계산을 다시 검증한다.
- 수열 탐정은 서버 보관 정답의 두 수와 순서까지 비교한다.
- 숫자 금고는 제출 문자열의 모든 정수 토큰을 뽑아 정렬한 배열이 문제 숫자를 정렬한 배열과 같은지 비교한 후 계산값을 검사한다.
- 성공한 경우에만 서버가 점수를 변경하고 전체 방에 새 점수를 방송한다.

### 재접속

- 브라우저 세션에 소켓 ID와 별개인 영속 `playerId`를 둔다.
- 연결이 끊기면 즉시 삭제하지 않고 `connected = false`로 표시한다.
- 30초 안에 같은 `playerId`로 돌아오면 사용자명, 점수, 제출 목록, 해결 여부, 방장 권한을 새 소켓 ID로 이전한다.
- 30초가 지나도 돌아오지 않으면 제거한다.
- 방장이 나가면 현재 연결된 첫 플레이어에게 방장을 넘긴다.
- 플레이어가 하나도 남지 않으면 방을 삭제한다.

권장 실서비스 보강 사항: 현재 기준 동작은 방을 서버 메모리에만 저장한다. 여러 서버 인스턴스, 서버 재시작 복구, 요청 속도 제한이 필요하면 공유 저장소/Socket.IO 어댑터/입력 스키마 검증을 별도 작업으로 추가한다.

## 7. 권장 모듈 경계

프레임워크 이름보다 역할 분리를 우선한다.

```text
equation/
  types                 공용 타입
  buildExpression       편집 상태 → 문자열
  evaluateExpression    안전한 정수 수식 계산기
  validateEquation      숫자 보존 + 등식 판정
  editorState           슬롯/괄호 생성 규칙
games/
  formula-workshop/     문제 생성 + 솔로 상태/UI
  sequence-detective/   수열 생성/유일성 검사 + 솔로 상태/UI
  number-vault/         문제 생성 + 솔로 상태/UI
multiplayer/
  types                 공개 payload와 상태 타입
  client                연결, 재접속, ack 요청
  server                방, 타이머, 제출 판정, 점수
```

게임 생성기와 검증기는 React/Vue/Flutter 등의 UI 상태에 의존하지 않는 순수 함수로 둔다. 서버와 클라이언트가 같은 검증 함수를 공유할 수 없는 플랫폼이면 같은 테스트 벡터를 양쪽에 적용한다.

## 8. 필수 테스트와 완료 조건

### 단위 테스트

- `buildExpression(['1','9','1','4','5'], [null,'=',null,'+'], [])`의 의미가 `19 = 14 + 5`가 된다.
- `12 + 3 × 4`는 24, `(12 + 3) × 4`는 60이다.
- `5 ÷ 2`, `1 ÷ 0`, 단항 음수, 소수, 괄호 불일치는 무효다.
- `19 = 14 + 5`를 원본 `19145`로 검증하면 정답이다.
- 숫자를 누락, 추가, 재정렬한 수식은 수식 공방에서 거절된다.
- 등호 0개/2개, 빈 좌변/우변, 값이 다른 양변을 각각 구분한다.
- 동일 괄호와 교차 괄호는 거절하고, 포함 관계의 중첩 괄호는 허용한다.
- 수열 생성 결과의 각 3번째 이후 항은 직전 두 항의 합이다.
- 생성된 수열 문제는 81개 시작 쌍 중 정답이 정확히 하나다.
- 생성된 숫자 금고 문제의 예시 정답은 제시 숫자 멀티셋을 정확히 사용하고 목표값을 만든다.
- 숫자 금고에서 숫자 누락, 추가, 중복 사용, 목표값 불일치는 거절된다.
- 난이도 경계 라운드 2→3, 4→5와 수열의 6→7을 검사한다.

### 멀티플레이 통합 테스트

- 방 생성, 참가, 정원 초과, 비방장의 시작 요청을 검사한다.
- 세 라운드의 난이도와 상태 전이 `LOBBY → PLAYING → ROUND_END → GAME_END`를 검사한다.
- 수식 공방의 동일 문자열 중복 점수 방지와 서로 다른 정답의 추가 득점을 검사한다.
- 수열/금고의 플레이어별 중복 득점 방지와 전원 해결 시 조기 종료를 검사한다.
- 조작한 클라이언트 제출이 서버에서 거절되는지 검사한다.
- 30초 내 재접속 시 점수와 권한이 유지되고 유예 시간 후에는 제거되는지 검사한다.

### 구현 완료 기준

- 세 솔로 모드를 실제로 연속 플레이할 수 있다.
- 수식 계산/검증과 문제 생성에 테스트가 있다.
- 멀티 범위가 포함되면 두 클라이언트가 같은 문제와 타이머를 보고 점수가 서버 기준으로 동기화된다.
- 기존 프로젝트의 lint, typecheck, 테스트, production build가 모두 통과한다.
- 구현 과정에서 바꾼 규칙이나 의도적으로 개선한 기존 한계는 결과 보고에 명시한다.
